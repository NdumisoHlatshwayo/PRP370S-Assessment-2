Project overview

RideConnect aims to make commuting more efficient through shared rides. The group's Agile Team Charter identifies user registration, driver trip offers, passenger ride search and booking, trip information, and seat availability as core requirements. The application screenshots supplied for this portfolio illustrate driver login, registration, ride creation, rider requests, acceptance and ride completion.

Project objective

Reduce the inconvenience and cost of commuting by helping people travelling in similar directions share transport.

My documented role

Wireframes Designer — creating key screen layouts and supporting usability. Group records confirm that I shared Figma wireframes for feedback in May 2026 and volunteered for Sprint 3 — UX Design in July 2026.

Assessment structure

Five Agile portfolio components, each supported by project evidence and individual reflection.

Evidence note: dated team records and individual reflections are documented throughout this portfolio. Original priority rankings and end-to-end device-test results have not been independently verified.

User Stories and Tasks

Evidence

Proposed user needs include driver login, publishing a ride offer, viewing rider requests and accepting passengers. Screenshots supplied show the corresponding app interfaces.

Design-oriented user story: As a driver, I want to post a ride with its route, departure time and seat count so passengers can find available transport.

Verified Trello task evidence: identifying user types, researching needs, creating personas, mapping user journeys, designing low-fidelity wireframes, and defining driver navigation and ride-management workflows. The board also uses Sprint 1–8 labels. These records show planned work, not independently verified completion.

Individual reflection

Working on wireframes encouraged me to consider both driver and passenger journeys. Driver registration, ride offers, and rider requests need clear screens and a logical sequence. The group discussed these views in May 2026. I learned to connect screen design with user goals rather than treating interface design as decoration.

Code evidence

Google Maps and location integration

The supplied RideConnect source archive contains src/components/RideMap.native.tsx, RideMap.tsx and RideMap.web.tsx. Native code uses react-native-maps and expo-location to request foreground location permission, display the user's location, and centre the map. Web code uses @react-google-maps/api, geolocation, markers, a test destination and the Google Maps DirectionsService to request a driving route.

Implementation status: map integration is present in the source code. Live functionality requires appropriate location permissions and Google Maps API configuration; a successful end-to-end test was not supplied.
